# 0004 — 浮起详情: 微任务重试 + 浮起后把用户原本那一格 focus 回来

- 状态:已接受
- 日期:2026-09-12
- 关联词条:`CONTEXT.md` § file-git-explorer(悬浮面板)
- 关联决策:ADR-0002(详情由官方 float 承载)、ADR-0003(用影子芯片拿 tabId)
- 触发:用户实测报告 —— 「点 diff 详情 / 文件详情,页签条先加一个 tag、闪一下、消失,才出现悬浮面板;
  同时右栏自己切回 git 树」

## 背景

ADR-0002/0003 定下的形态是:详情**以官方 float 承载**,本插件通过影子芯片拿到 `tabId` 后立刻
`ctx.sidebarRight.float(tabId, rect)`。落地后有两个只在真浏览器里看得见的时序问题。

**(1) 页签条上"闪一下"。** 新页签挂载的那一次 commit 里直接调 `sidebarRight` 必抛
`sidebarRight: no session surface is mounted`:官方座位的绑定写在
`useEffect(() => bindService({...}), [..., surfaces])`,新页签让 `surfaces` 变了,那一轮 flush
先跑整棵树的卸载阶段(座位释放绑定)、再跑装载阶段(子先父后),本插件的芯片 effect 正落在
"已释放、尚未重绑"的空隙里。原实现用 `setTimeout(..., FLOAT_RETRY_MS = 60)` 重试,于是这 60ms 里
详情页签已经在页签条上被画出来了。

**(2) 右栏自己跳页签。** dockkit 的 float reducer 会把来源 pane 的 `activeTabId` 改成
`tabs[max(0, index - 1)]`(内部 `W3(tabs, s)`, index = 被浮起页签的下标),而详情页签总是追加在
末尾。从「文件」页签点文件时,左边那一格正是先前打开的 git 树 —— 观感就是"右栏自动切回 git 树了"。

## 决策

**(1) 座位绑定空隙的重试走微任务,不走定时器。** 空隙在**同一轮 effect flush 的收尾**就补好了,
所以 `Promise.resolve().then(...)` 足够:微任务在 flush 之后、paint 之前执行,详情页签**一帧都不会**
出现在页签条上。`retryFloat` 前 2 次用微任务,之后才退回定时器;"量不出 rect"(右栏还在展开、没有轨道)
那一路仍用定时器 —— 那是真的得等下一帧。`close()` 与 `float()` 共用这条重试,顺序仍是"先关后浮"。

**(2) 浮起成功后把"用户动手之前选中的那一格" focus 回来。** 不去猜"左边那格应该是谁":用一条
**捕获阶段**的 `click` 监听,在官方的点击处理之前读页签条上 `aria-selected` 的那一格(点在页签条
本身上时跳过 —— 那是用户在切页签),浮起成功后 `ctx.sidebarRight.focus()` 回去。focus 与 float 落在
同一拍,所以连"先跳过去再跳回来"的闪动都没有。

## 备选方案(被放弃的)

| 方案                                              | 放弃原因                                                                                                          |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 保持 60ms 定时器, 用 CSS 把"待浮起"的页签临时隐藏 | 治的是症状: 中间态仍然存在, 且要往官方 DOM 上贴样式、还要处理"浮起失败要还原"                                     |
| 用 `useLayoutEffect` 提前调用                     | 布局阶段子先父后 ⇒ 芯片 effect 跑时座位绑定**还是旧的**, `float()` 对旧 layout 是静默 no-op, 页签索性永远浮不起来 |
| 用 `focus()` 修"跳页签"改成 focus 左邻            | 左邻是谁由官方 store 决定, 正是出问题的那条规则; 用户在看「文件」时它照样跳到 git                                 |
| 记住 `sidebarRight.active()` 的结果当回落目标     | 需要额外维护"什么时候读的", 容易陈旧; 直接读 DOM 的当下选中态没有这个问题                                         |
| 让详情页签不参与激活(打开即非活动)                | 官方 `openContent` 必然把新页签设为活动; 没有"后台打开"的公开选项                                                 |

## 后果

- **正面**:详情**只以浮层出现** —— 页签条上不再闪现;右栏停在用户原本看的那一格。
- **代价**:两条都是对官方时序的**依赖**,官方改掉这两处(座位绑定改到 layout effect / float 改回落点)
  时,本插件这两段会退化成无害的空转(多一次 focus 到同一格、多试一次微任务),不会报错。
- **守门**:仓库根 `scripts/verify-client-bundles.mjs` 里新增一项离线检查 —— 桩里让 `float()` 第一次必抛、
  `setTimeout` 只记账不执行,断言"同一拍内重试过"且"focus 打到了用户那一格"。退回定时器或删掉 focus,这一项就红。
  (真浏览器验收仍走插件 README 的验收清单第 5、6 条。)
