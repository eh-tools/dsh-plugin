# 0002 — file-git-explorer 的详情一律由官方 float 承载,不自绘悬浮面板

- 状态:已接受
- 日期:2026-09-11
- 关联词条:`CONTEXT.md` § file-git-explorer(悬浮面板 / 详情)

## 背景

需求:官方文件树点开的文件详情、以及 git 的 diff 细节,都要落到**右侧栏左侧的悬浮面板**上 —— 视口 1/2 宽、满高、紧贴右栏左缘、正对齐,**同一时间只有一个**,切换文件就地换内容。

官方右侧栏自带 **float 宿主**:`ctx.sidebarRight.float(tabId, rect)` 是公开接口,矩形**原样生效**、悬浮面板数量无上限、可多个并存,并且官方 FloatLayer 免费提供圆角外壳、可拖拽头部、缩放手柄、关闭与「送回侧栏」按钮。默认几何是 380×300、每层错开 24px 的**级联**(本来就重叠),没有任何平铺 / 吸附 / 避让 / 贴边逻辑。

另一条路是**自绘悬浮面板**:frame 级可加座位 `shell.overlay`(v0.2 的悬浮面板正是注册在它上面),几何与外观完全自控。

而官方六种正文渲染器的可复用性实测为:**markdown 与代码可复用**(`@deepseek-ai/dsh-client-ui-primitives` 导出了 `MarkdownText` 与 `CodeBlock`,而该模块是浏览器种子表第 8 项),**text / image / html / pdf 不可复用**(正文组件未导出,`documentPreviews` 只是元数据注册表,`renderSlot` 只允许渲染 `root`)。

## 决策

1. **详情一律用官方 float 承载**,并且**文件内容也不自己渲染**:让官方 text 类型照常接管地址,本插件只把这个页签**浮起来**。于是 markdown / 代码 / 图片 / html / **pdf 全部是官方原版**,本插件零正文渲染代码。
2. **位置与尺寸由本插件自算**(贴右栏左缘、视口 1/2 宽、满高、正对齐),因为官方默认级联不满足需求。
3. **只有 diff 需要本插件自建一个页签类型** —— 官方正文渲染的是「文件内容」而非 diff,没有现成路径。该页签同样用 float 浮起,内容用官方 `DiffBlock` 渲染(统一 diff 拆成 hunk 的解析放在 host 侧纯函数里)。
4. **同一时间只有一个面板**:每次浮起新的之前,先关掉上一个悬浮面板的页签;位置用同一套 rect 计算,因此观感等同「就地换内容」。

## 备选方案(被放弃的)

| 方案                                             | 放弃原因                                                                                                                                                                                                              |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 自绘悬浮面板(`shell.overlay`)+ 自己渲染正文      | 外观与几何能完全自控(可强制贴边、无多余按钮、复刻 v0.2 观感),但 markdown 之外的官方渲染器不可复用:html 匹敌不了官方的相对资源打包,pdf 要自带 pdfjs,**等于用"多写几百行 + 两处渲染退化"换外观**;而需求要的正是"零退化" |
| 官方浮卡外壳 + 自己渲染正文                      | 既保留了官方悬浮面板那个去不掉的「送回侧栏」按钮,又没换来内容上的好处(仍要自己处理 pdf),两头不占优                                                                                                                    |
| 只用官方 float 但不浮起、改成官方 `split()` 分栏 | 分栏把面板关在**右栏列内**(最多两格、各占一半、divider 限 20%~80%),不是"侧栏左侧",且宽度是右栏的一半而非视口的一半                                                                                                    |

## 后果

- **正面**:md / 代码 / 图片 / html / pdf 的观感与官方逐字一致;拖拽、缩放、关闭、回送等外壳零代码;本插件卸载后官方行为原样还原。
- **另一条已知代价**:官方**没有移动 / 缩放"已浮起"面板的接口**(`ctx.sidebarRight` 只有 close/focus/float/dock/split,而 `float()` 对已浮起页签是 no-op),所以 `rect` 只在浮起那一刻算得准,换窗口尺寸不会自动重排;
  本插件后来加的浮窗「全屏」开关也只能走 CSS 覆盖(`inset:0!important` 压掉浮窗 inline 的几何,不改官方那份 `rect`)—— 好处是退出全屏能原样回去。
- **代价(已知且接受)**:
  - 悬浮面板头部**自带「送回侧栏」按钮且不可移除**(官方 chrome),误点会把详情变成右栏页签;
  - 悬浮面板**不吸附**右栏边缘,可以被拖走(因"同一时间只有一个",拖走不会与其他面板重叠,故不影响"不重叠"这条要求);
  - 官方 chrome **没有可注入的槽**,所以「复制内容」只能放进本插件自己渲染的那一格页签芯片(见 ADR-0003)。
- **时序约束**:`float()` 只对**处于 docked 状态**的页签生效,所以流程必然是「先作为页签打开 → 再浮起」;且在无已挂载会话座位时会抛错,调用点需容错。

## 修订(2026-09-13)

上面「代价」里那句 **「送回侧栏」按钮不可移除** 已不成立:本插件后来用纯 CSS 把它藏掉了
(`[data-dockkit-float]:has([data-dockkit-float-title] .fge-doc-name) [data-dockkit-float-dock]{display:none}`)。

- **为什么当时以为不可移除**:该按钮是 dockkit 渲染的官方 chrome(`_iconButton_17p4l_408`),确实**没有可注入的槽**
  —— 但这只说明"不能靠座椅替换",不等于"不能用 CSS 藏"。原判断把"没有槽"外推成了"改不了",这是那次推演的漏洞。
- **为什么现在要藏**:它的效果是把详情变回右栏页签,与本条的**第 4 条决策**("同一时间只有一个面板 + 详情只以浮层出现")
  方向相反;误点之后还得再点一次同一个文件才重新浮起。
- **限定条件(重要)**:官方浮动宿主是**所有页签共用**的,别的页签(拖页签 / 页签菜单)被浮起来时也长着同一个按钮 ——
  所以选择器必须按"这是不是本插件的详情浮窗"限定,判据取标题里的文件名芯片(`.fge-doc-name`)。裸选择器会把别人的一起藏了。
- **对上面备选方案表的影响**:那张表里"官方浮卡外壳 + 自己渲染正文"被放弃的理由之一是"保留了去不掉的「送回侧栏」按钮"
  —— 该条论据**不再成立**,但该方案被放弃的**主因**(仍要自己处理 pdf / html,两头不占优)不变,故决策不变。
- **仍然成立的代价**:拖页签 / 页签菜单依旧能把详情变回右栏页签(这条路没有堵),`adoptFloat` 的幂等语义照旧需要。
