# 0005 — 提交历史用「聚焦提交」取代就地展开

- 状态:已接受
- 日期:2026-09-13
- 关联词条:`CONTEXT.md` § file-git-explorer(聚焦提交 / 提交历史 / git 页签分栏)
- 关联决策:ADR-0004(详情只以悬浮面板出现)、ADR-0002(详情由官方 float 承载)
- 触发:用户口径 —— 「点一条提交,这条的内容自动接管下栏、只显示这一条,顶部带返回键;
  返回时不要重新刷新提交历史」

## 背景

v0.7 的 git 页签里,点一条提交是**就地展开**:提交行下面直接铺出说明与文件清单,再点收起;
`CONTEXT.md` 当时把它写成了「页签内没有视图栈、没有返回按钮」的一部分 —— 记录在案的取舍是
**页签内不引入导航层级**,靠"点开/收起"就够。

落地几轮之后这个形态在**窄栏**里露了两个问题:

1. **空间被挤**:右栏最窄只有 200px。展开的说明(尤其是带 body 的 commit message)加上文件清单,
   会把同一栏里**其他**提交全挤出去 —— 用户要对比两条提交就得反复展开/收起。
2. **「选中」这件事没有落点**:列表里没有任何东西表示"我正在看的是这一条"。

而 v0.7 的另一个形态(`gitViews` 里所有视图状态**按会话缓存**、重挂不丢,见 README 实现事实 §10)
恰好把"进一个子视图再回来"所需的成本降到了近乎零:列表状态本来就不会丢。

## 决策

**点一条提交 = 聚焦它**,而不是就地展开:

- 下栏**整栏**在**历史列表态**与**聚焦态**之间二选一(两个形态共用同一个滚动容器);
- 聚焦态顶部是标题栏:`← 返回` | `作者 · 时间`(可截断)| **hash 胶囊**(与返回键永不被截断);
  **Esc 也能返回**,并接进插件那条唯一的 keydown 做分层(终端 → 悬浮面板 → 分支小浮窗 → 聚焦);
- 进入时下栏自动放到最大(`GIT_SPLIT_MIN`,即下栏 60%),返回时还回进聚焦前的比例;
  **但聚焦期间自己拖过拖柄就以新值为准** —— 一次点击不该覆盖用户刚表达的偏好;
- 返回**不重新拉取、也不补刷**,并把列表滚回离开时那一处;聚焦期间 turn 结束的自动刷新**挂起**;
- 聚焦态与列表态、以及展开的说明一起**按会话缓存**(§10 那条不变式,不开特例);
- 整栏一层极淡的品牌色底,作为"我不在列表里"的容器感。

`focused` 取代了原来的 `expanded` 表(`toggleCommit` / `withExpanded` 一并退场)。

## 备选方案(被放弃的)

| 方案                                    | 放弃原因                                                                      |
| --------------------------------------- | ----------------------------------------------------------------------------- |
| 保留就地展开,另给一个入口进聚焦         | 两套展开状态并存,代码与心智都更重;同样的信息有两个住处                        |
| 聚焦时把**整张 git 页签**(含上栏)都接管 | 上栏是"当前工作区 diff",与"我在看哪条历史"是两件事,不该被后者顶掉             |
| 列表里只留标题行,点进去才拉详情         | 失去"扫一眼看说明"的能力,而且请求变多                                         |
| 返回时重新拉一次历史(保证最新)          | 用户明确要求"返回不要重新刷新";而且刷新会重置滚动位置、把"刚看到哪儿"丢掉     |
| 用 ref 存列表滚动位置                   | 组件会被卸载重挂(点文件开 diff 就会),ref 跟着没;得进 §10 那份按会话缓存       |
| 聚焦态整栏用不透明底色做容器感          | 右栏只有 200px,一块实底太过;用 6% 品牌色 `color-mix` 既够区分又不像换了个面板 |

## 后果

- **正面**:一条提交在窄栏里拿到整栏空间;列表不再被展开的内容顶走;「我正在看哪条」有了明确落点
  (整栏 + 返回键 + 品牌色底)。
- **代价**:git 页签**第一次**有了导航层级(列表 ⇄ 聚焦)与一枚返回键 —— `CONTEXT.md` 里原先
  "页签内没有视图栈、没有返回按钮"的口径随之作废,已改写。聚焦态下**看不见列表**(要返回才能换一条)。
- **守门**:`scripts/verify-client-bundles.mjs` 的离线项断言「点提交走 `focusCommit`」「`toggleCommit` /
  `withExpanded` 已退场」「聚焦态有返回键 / `focusEsc` / 返回时还原滚动位置」「聚焦态有 `data-focus` 淡底」
  「标题栏的不透明契约: 底座实色 + 强调色只许叠加」;
  行数组那份工厂还被**真调用**了一遍(注入假 `h`, 断言顺序 / 深度 / `isLast` / `continues`)——
  起因是顶层调用把 `[]` 传错格子那次事故, 而"按目录归类"只在有目录时才走到那条分支, grep 式护栏没拦住。
  真浏览器验收走插件 README 验收清单第 4、5 条(自动放大与还原、返回不刷新且滚动位置还在、Esc 分层、
  hash 胶囊复制完整 hash 且不连带聚焦)。
- **不变的部分**:聚焦里的详情依旧走 host 的 `show`(与就地展开时代同一个路由、同一份数据);
  点文件依旧进**悬浮面板**(ADR-0002/0004 的形态没动)。「聚焦提交」与「详情」是两件不同的东西,
  `CONTEXT.md` 里已互相加了 `_Avoid_` 提示。
